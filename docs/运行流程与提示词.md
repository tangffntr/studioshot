## 二、完整运行流程（从用户输入到图片输出）

### 阶段 A：用户上传产品图（可选）
- `POST /api/products` → 存 OSS → 建 products + media 记录
- 无产品图时可直接纯文本对话（Agent 全模态）

### 阶段 B：提交任务（admit-then-run）
- `POST /api/jobs` → 插入 job（status: queued）→ 立即返回 jobId → 异步执行
- payload 含 mode/templateId/referenceScene/skuProducts 等参数

### 阶段 C：任务调度分流（runner.ts）
按优先级依次判断 jobMode：

| 优先级 | 模式 | 触发条件 | 执行器 |
|--------|------|---------|--------|
| 1 | video | mode="video" | runVideoJob（可灵图生视频） |
| 2 | tryon | mode="tryon" | runTryonJob（OutfitAnyone 试穿） |
| 3 | batch-sku | mode="batch-sku" | runBatchSkuJob（批量场景替换） |
| 4 | scene-swap | mode="scene-swap" | runSceneSwapJob（单次场景替换） |
| 5 | pipeline | 有 templateId | runPipelineJob（模板套图 14 图） |
| 6 | agent（默认） | 其他 | runAgentLoop（LLM 自主编排） |

### 阶段 D：执行
- **Agent 模式**：主 LLM 自主调用工具（analyze → generate → quality → 收敛）
- **Pipeline 模式**：确定性遍历模板 14 图位（analyze → 渲染 prompt → 逐图生图）
- **其他模式**：各自的专用流程

### 阶段 E：模型调用（Model 门面）
```
Model.image("main-image").generate({prompt, referenceImages, size}).run().save(path)
  → resolveSlot("main-image") → task_slots → models → vendors
  → getAdapter(vendor.adapter) → grsai/openai-chat/aliyun-tryon/kling-video
  → 解密凭证 → 调适配器 → 记 api_calls → 落 OSS → 建 media 记录
```

### 阶段 F：SSE 实时进度推送
- `GET /api/events` 单一 SSE 流
- 事件类型：job.started/progress/completed/failed, agent.message, tool.call/result, media.completed
- 15s 心跳保活

## 三、所有系统提示词（原文）

### 3.1 Agent 主循环 SYSTEM_PROMPT
> 文件：`agent/loop.ts:28-49`
> 作用：驱动 Agent 模式的主 LLM 行为

```
你是一个电商出图 Agent，负责根据用户指令生成电商图片。你是全模态的，可以与用户自由对话，也可以直接生成图片。

核心原则：
- 用户给了产品图（消息中含 media id）→ 先 analyze_product 分析，再 generate_image 出图
- 用户没给产品图，只是描述需求（如"生成一只猫"）→ 直接 generate_image（不传 referenceMediaIds），根据用户描述生成
- 用户只是聊天提问（不需要图片）→ 直接文字回复，不调任何工具

工作流程（有产品图时）：
1. analyze_product 分析产品图（只调一次）
2. generate_image 生成图片（传入产品图 referenceMediaIds 保证保真）
3. check_quality 质检
4. 通过→总结结束；不通过→最多重试1次

工作流程（无产品图，纯描述出图时）：
1. 直接 generate_image（referenceMediaIds 传空数组，按用户描述生成）
2. check_quality 质检
3. 通过→总结结束

收敛规则：
- 最多生成 2 张图，之后必须文字总结并结束
- generate_image 后你会看到生成的图，据此判断
- 不需要图片时直接文字回复
```

## 四、Agent 工具定义（LLM 可调用的）

| 工具名 | 描述（给 LLM 看） | 输入 | 输出回灌 |
|--------|------------------|------|---------|
| `analyze_product` | 分析产品图：识别类目、颜色、材质、卖点等属性。返回结构化 JSON。在生成图片前应先分析产品。 | `{mediaId}` | text（属性 JSON） |
| `generate_image` | 生成电商图（主图/场景图）。传入 prompt 和可选参考产品图（图生图保真）。生成后你会看到结果图，可判断是否需要重做。 | `{prompt, referenceMediaIds[], size, purpose}` | text + file（base64 图片，LLM 下一回合能"看见"） |
| `check_quality` | 质检已生成的图片：检查产品外观保真、文字清晰度、构图合理性。返回评分(0-1)和问题清单。若不通过，主 Agent 应重做 generate_image。 | `{mediaId, criteria[]}` | text（评分+问题） |

### 图片回灌机制（A3 闭环）
- `generate_image` 的 `toModelOutput` 返回 `{type:"file", data:base64, mime}` 
- 工具执行后，图片作为**独立的 user message**（多模态 image_url）注入对话历史
- 主 LLM 下一回合能"看见"刚生成的图，据此判断质量、决定重做

### 5.4 Pipeline 完整流程
```
1. 加载模板 + 14 图位（template_slots 按 sequence 排序）
2. VLM 分析产品属性（category/color/material/shape/style）
3. renderAllSlots: 骨架占位替换 → 14 个具体 prompt
4. generateStyleLock + applyStyleLock: 风格锁定文本拼到每个 prompt 开头
5. 读源产品图 base64（图生图参考，保证保真）
6. for slot in 14 slots（确定性遍历）:
     Model.image(slot.taskSlotKey).generate({prompt, referenceImages:[源图], size}).run().save()
     media 记录 slotCode(H1/D3...) + sortOrder
     emit SSE 进度
7. 汇总 mediaIds，job done
```

## 六、Agent 循环机制详解

### 消息历史结构
```
[
  { role: "system", content: SYSTEM_PROMPT },
  { role: "user", content: "用户指令 + 产品图 media id" },
  // 每轮循环追加：
  { role: "assistant", content: "文本", tool_calls: [...] },  // LLM 回复
  { role: "tool", tool_call_id: "...", content: "文本结果" }, // 工具结果（纯文本）
  { role: "user", content: [{type:"text"},{type:"image_url"}] }, // 图片回灌（多模态）
]
```

### 图片回灌的关键设计
- OpenAI 标准 `tool` role 不支持多模态 content（MiMo 严格遵循会报 `text is not set`）
- 因此**工具文本结果**放 `role:"tool"`（纯字符串）
- **工具图片结果**放独立的 `role:"user"`（多模态 image_url）
- 这是 A3 闭环的工程实现：主 LLM 下一回合能"看见"生图

### 收敛控制
- MAX_STEPS = 25（硬上限）
- SYSTEM_PROMPT 约束"最多 2 张图"
- 无 tool_calls → 循环结束
